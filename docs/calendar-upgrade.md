# 달력·부서 인원 개선 · 2026-11-12

## 관리자에게 신청이 보이지 않는 문제

기존 직원 화면과 관리자 처리 화면은 모두 `LeaveRequest`를 읽었습니다. 공개 서버에서 가상 신청을 만들자 관리자 화면을 다시 GET한 응답에는 같은 신청 ID가 나타났습니다. 기존에 열어 둔 관리자 HTML에는 신청이 추가되지 않았고, 기존 JavaScript에는 신청 목록을 갱신하는 코드가 없었습니다. 재현된 문제는 다른 DB 사용이 아닌 **열어 둔 화면의 갱신 누락**입니다. 진단 신청은 취소했고 기존 신청·예약을 수정하지 않았습니다.

직원 달력, 관리자 달력·상세 내역, 관리자 홈의 승인 대기 건수를 5초마다 다시 조회합니다. 선택한 달 밖의 대기 건수와 이동 링크도 표시합니다. 직원·관리자는 같은 서비스 함수와 같은 신청 테이블을 사용합니다.

## 화면과 규칙

- 직원: 잔여일, 월간 달력, 날짜별 자기 신청·상태, 하루/오전/오후 신청, 해당 시간대의 부서 인원 요약.
- 관리자: 부서·승인 대기 필터, 날짜별 상태 건수, 직원·부서·구분·처리, 부서 기본 인원과 날짜별 오전/오후 인원 설정.
- 차량: 차량 선택 → 날짜 → 점유 시간/가능 시간 → 시간 선택 → 예약. 본인 예약만 식별·취소하며 동료의 이름과 사용 메모·예약 ID는 보내지 않습니다.
- 근무 가능 인원은 시간대별 근무 예정에서 승인된 연차의 **직원 수**를 뺍니다. 대기는 차감하지 않습니다. 하루는 오전·오후를 모두 검사합니다.
- 신청과 승인 시 서버가 최소 인원을 검사합니다. 승인은 SQLite IMMEDIATE 트랜잭션 안에서 최신 인원·잔여일을 확인하고 상태·차감·이력을 함께 처리합니다.
- 같은 날짜라도 오전과 오후는 각각 신청할 수 있습니다. 같은 시간대의 자기 대기·승인 신청, 하루와 반차의 겹침은 막습니다. 여러 날짜 일괄 신청은 기존에도 지원하지 않았으므로 추가하지 않았습니다.
- 신청 시 소속 부서를 기록합니다. 이후 부서 이동이 있더라도 해당 신청의 승인·인원 계산은 신청 당시 부서를 기준으로 합니다.

## 기존 데이터 보존

`0002_department_calendar`는 기존 신청·예약·잔여일·증감 이력을 삭제하지 않습니다. 기존 하루는 하루로, 기존 반차는 **시간 확인 필요**로 마이그레이션합니다. 관리자가 오전·오후를 확인하면 별도 처리자 이력을 기록합니다. 확인 전 승인된 반차는 인원 계산에서 오전·오후 모두에 보수적으로 포함합니다.

로컬 DB를 변경 전 SQLite backup API로 백업했으며, 변경 후 기존 신청·계정·원장·예약·위키 문서/버전/문단의 원래 컬럼과 값을 PK별로 비교해 동일함을 확인했습니다.

현재 Render Free는 임시 SQLite를 사용하므로 **기존 서비스의 재배포 자체가 현재 DB를 초기화**합니다. 이를 마이그레이션의 데이터 보존과 혼동하지 않습니다. 기존 서비스와 main 브랜치는 유지하고, `calendar-upgrade-20261112` 브랜치의 별도 Free 검증 서비스를 사용합니다. 현재 운영 중인 Free 서비스에는 DB 백업 다운로드 기능이나 Shell이 없어 완전한 원격 DB를 추출할 수 없습니다. 따라서 기존 주소를 데이터 손실 없이 교체했다고 표시하지 않습니다.

- 부서: 운영지원부 · 기본 근무 예정 5명 / 최소 필요 3명.
- **2026-11-18:** 가상 지원으로 신청 → 관리자 같은 날짜에서 대기 확인 → 승인 → 직원 잔여일·상태 확인.
